# 分析方法与自动规则

本文件定义拟实现的方法，不表示模型已集成或已达到某项精度。所有阈值需通过测试集评估后固定版本。默认面向流行歌曲的离线处理，不宣称适用于全部音乐类型。

## 1. 基础预处理

1. ffprobe 检查音频流、采样率、声道、时长和编码；计算输入 SHA-256。
2. FFmpeg 解码为 `pcm_f32le` WAV，保留原始采样率、声道、起始静音、速度和动态。
3. 输出 manifest，明确原曲 `t=0`。每个适配器独立重采样，不能把帧下标直接当统一时间。
4. 片段结果按 `t_original = t_local + segment_start - known_padding` 恢复时间；补零仅在模型输入中存在，导出时裁到真实音频范围。
5. 不从较高采样率推断音源品质；不做未经需要的降噪、响度归一化或静音裁切。

## 2. 声源分离

**工具：audio-separator，首选 `htdemucs_ft.yaml` 四轨模型。** 输出 vocals、drums、bass、other。保留原始混音供和弦、节拍、结构、曲风和情绪分析。

- 模型权重首次下载后记录哈希，后续固定。分离轨不作为精确的乐器清单。
- 记录输出时长、采样率、增益处理与偏移；不通过独立峰值归一化后的音量推断原曲声部比例。
- RoFormer 是人声分离不理想时可评估的替代方案，不在初版默认叠加多个大模型。
- 四声部不等于“旋律、和声、节奏、音色”四类信息。

## 3. 旋律时间线

**工具：Basic Pitch、torchcrepe、Essentia PredominantPitchMelodia；自研候选选择器。**

### 3.1 候选提取

- 在人声轨上运行 torchcrepe，得到逐帧基频和周期性指标；默认 Viterbi 解码，结合静音门限及迟滞门限排除伪发声。
- 在同一声部上运行 Basic Pitch，得到音符起止和 MIDI 音高候选。保留 onset 激活用于同音重复，不将起音等同于歌词字边界。
- 在器乐伴奏或完整混音上运行 PredominantPitchMelodia，得到器乐显著旋律候选，`guessUnvoiced=false`。
- 人声中仍可能混有伴唱；所有候选均不保证属于主旋律。

### 3.2 自动选择

采用有状态的“人声优先”策略：稳定有效歌声区间优先人声候选；短换气保持空隙；持续无歌声且存在可靠器乐候选时转向器乐。状态切换需迟滞和最短持续证据，避免每帧选择最大音量或最高音。

候选依据包含各模型原始分数、有效帧比例、连续性、时长和突跳情况。不同模型的分数不直接比较大小，也不冒充校准概率。优先级及门限保存在配置中；先在有标注片段上验证再固定。第一版不训练新模型。

### 3.3 事件与轮廓融合

- 基频换算为 `midi_float = 69 + 12 * log2(f0_hz / 440)`；仅对有效正频率计算。
- Basic Pitch 音符与连续音高候选进行时间覆盖和音高一致性检查，抑制重叠伴唱误检与明显八度错误。
- 器乐候选的音符事件可由同源音符候选或起音包络加音高稳定片段生成。若声部仍为复音，导出的主旋律归属保持 estimated。
- 无效区间不插值为声音；同音重复保留独立起音；颤音不逐帧拆成新音符。
- Basic Pitch 当前默认最短音符约 127.7 ms，需要测试短音漏检。马达执行限制在下游简化，不在音频分析层删除真实短音。

**输出：**音符起止、MIDI 音高、连续轮廓、声部来源、有效/未知区间、原始质量指标。

## 4. 和声时间线

**工具：BTC 大词表模式（170 类，显式 `--voca True`）与 mir_eval。**

1. 以完整混音运行官方前处理和推理，输出和弦标签区间。
2. 合并相邻同标签；对很短的跳变基于邻域证据处理，但不把所有边界量化到拍点。
3. `mir_eval.chord.encode` 加 `rotate_bitmap_to_root` 转成绝对十二音类；根音 C=0，C#=1，…，B=11。
4. 用前后集合交、差运算计算保持、增加、离开音。和弦回归由历史集合/标签匹配得到。
5. 分开保存 no_chord、unknown 和模型失败；不要把识别不清全部变成无和弦。

输出音类代表标签的理论组成，不承诺还原录音中每个装饰音、声部八度或配器。原曲调性只有实际分析器输出且记录来源时才导出，不能从单个和弦猜全曲调性。

## 5. 节奏时间线

**工具：Beat This!，初版 `final0`，`dbn=False`。**

- `File2Beats` 输出 beats 和 downbeats，以此建立唯一正式节拍时间线。
- 对已确认单位的拍间隔计算局部 BPM；用窗口内稳健统计平滑，不反向用单一 BPM 填满整首歌。
- 第一拍之间统计拍点得到小节分组候选，不足以自动确定 6/8 等完整拍号。拍号不能确定则 null。
- 缺失第一拍时仍输出普通拍点；节拍整体失败时标 unknown，不伪造规律振动事件。
- 半速/倍速与相位错误需在评估集上检查，不能靠任意“流行歌 BPM 区间”一概纠正。

## 6. 段落时间线

**工具：All-In-One，`harmonix-all`。** 提取功能段落标签与边界；不覆盖 Beat This! 的正式拍点。

相邻相同功能标签也可能是两个独立段落，保留模型检测到的边界及实例编号；显示合并需独立策略。没有足够证据的名称记 unknown。

若结构模型失败，为描述分支生成连续固定窗口（配置草案为 30 秒，属于工程回退参数），最后窗口覆盖到真实结尾，名称为 unknown、source 为 fallback。窗口不伪装成主歌/副歌。

## 7. 音乐描述表

### 曲风、乐器与质感

- Essentia 的 Discogs 曲风模型、MTG-Jamendo 乐器模型提供多标签分数；读取模型元数据的类别顺序和输入要求。
- Qwen2-Audio 基于实际片段生成质感候选。初版词表：拨弦、持续、短促、明亮、偏暗、柔和、颗粒、未知；词表是项目约定，不是客观音乐分类。
- 通过 JSON 格式、字段类型、词表、长度及适用时间检查输出；失败有限重试后置空。格式检查只能保证结构正确，不能证明语义正确。
- 若标签模型与语言模型冲突，记录各自结果和冲突，不让语言模型覆盖音符、和弦或拍点。
- 速度描述复用 rhythm，不重复估计另一套节拍。

### 情绪与氛围

- 对实际片段调用 Music2Emo，输出 valence、arousal、predicted_moods；保存模型原生量表及出处。
- 当前实现对输入音频做特征汇总，不是默认输出逐秒情绪轨迹。逐片段分析是本项目组合策略，需要单独评估。
- 极短片段使用带上下文的分析窗口或标记证据不足；保留 analysis_start/end 与 applies_start/end，不能隐去上下文。
- 不在分析结果里将全曲 min-max 拉伸成“最悲伤到最快乐”。映射需要 0–1 时按明确量表转换，另存，不覆盖原始值。
- 片段之间的视觉渐变是映射策略，不标成模型测出的真实情绪变化。
- 模型内部估计的和弦/调性仅作其特征，不回写并覆盖正式 harmony 时间线。

## 8. 歌词与背景

**第一版输入已有歌词；自动转写留作后续独立功能。** 没有歌词、没有资料也能完成音频分支。

1. SOFA 使用人声片段、匹配语言的模型、字典/G2P 与对应歌词进行强制对齐。
2. 长歌曲需先切片并建立文本顺序候选，重复段落采用单调顺序约束。完整长歌词的切片与匹配属于待开发适配逻辑，不宣称 SOFA 一次调用即可完成。
3. 聚合对齐结果为句/段落；失败区间保留 unknown。仅有歌词语义但无可靠对齐时，保存整曲语义，不伪造局部时间。
4. 文本模型按固定字段输出叙事、主题、意象、证据位置。初版可复用已部署语言模型，独立接口允许之后替换轻量文本模型。
5. 背景摘要只读取提供的来源材料；未提供资料时留空。音频情绪、歌词情感、背景事实分别保存。

## 9. 自动后处理

- 检查秒数有限、非负、结束大于开始、不越过原曲；预期连续的时间线检查覆盖与空隙。
- 保留 raw 与 normalized 两层。任何过滤/合并都记录策略版本和原因。
- 事件按时间排序；跨片段输出去重时保留同音重新起音，不按音高一键去重。
- 字段来源包括模型、权重哈希、参数、运行ID；未提供可信度时为 null。
- 输出 `complete/partial/failed` 和逐模块状态。一个模块失败不伪造其他模块成功。
- 任何极端值/冲突筛查都不是“自动保证正确”；准确性由独立评估衡量。
