# 给 AI 的接手指令

先把仓库链接发给 AI；能克隆仓库的编码工具请克隆后工作。若它只能读网页，要求它先读取这些具体文件，不要只看 README 推测内容。以下两个角色分别使用，不要让 AI 同时重做预处理。

## 视觉队友复制这一段

```text
请读取这个仓库：https://github.com/Fragile-greensleeves/cross-sensory-music-preprocessor
先按顺序读取 README.md、docs/framework.md、docs/handoff.md、docs/package-format.md、handoff/qingtian/manifest.json，并检查 handoff/qingtian/song-package.json 的实际字段。

我的任务是视觉转译。基于已有最终歌曲包开发可运行的视觉原型，不重新训练或运行音乐分析模型，不修改原始分析数据。
使用旋律音高显示上下起伏的线条，起音建立节点、停顿断开；使用和弦 pitch_classes 在十二音类固定位置呈现光斑；按 descriptions 的应用时间范围，用固定预设映射质感、效价和唤醒度，平滑过渡。先读取 emotion.scale 再归一化，未知标签用中性预设。
目标设备是外挂式彩色近眼信息窗，先交付屏幕可预览版本；不要假设已有舞台空间定位或全视野 AR。优先沿用我们的实际前端/Unity 工程；若没有工程，先建立最小可运行预览。
与触觉共用原曲时间、音域配置和暂停/跳转状态。歌词只在收到本地完整版时使用，当前字放大、整句在下面；没有歌词也能运行。
请先列出真实字段到视觉参数的对应关系、缺失数据的处理方式，再开始实现；交付运行步骤、可调配置、预览与暂停/跳转/空值验证记录。若无法访问数据，请明确指出，不要编造字段、歌词或结果。
```

## 触觉队友复制这一段

```text
请读取这个仓库：https://github.com/Fragile-greensleeves/cross-sensory-music-preprocessor
先按顺序读取 README.md、docs/framework.md、docs/handoff.md、docs/package-format.md、handoff/qingtian/manifest.json，并检查 handoff/qingtian/song-package.json 的实际字段。

我的任务是手套触觉与灯带转译。读取已有最终歌曲包，不重新运行分析模型，不改写原始音符或拍点。
设备是 ESP32-S3-Zero、三个手背旋律马达、一个手腕节拍马达、两块 DRV8833 和可寻址灯带。三个马达在沿食指方向的手背区域，不在食指指节上。马达强度固定，只改变位置、触发时间和脉冲时长。
把 melody.notes 的每个音符起点映射到固定低中高音区马达；同音重复重新触发。用 rhythm.beats 的实际拍点触发手腕，确认的小节第一拍用较长单次脉冲。灯带位置随有效音高变化，低音靠手腕、高音靠指根。不要逐字触发、逐帧反复振动、按平均 BPM 补拍，或将情绪映射为振动强弱。
先做事件导出与软件模拟，再接入真实硬件。共享配置包含音域、音区分界、脉冲时长、最小间隔、编号与延迟；实际 GPIO、灯带型号、供电参数按我们的元件确认，不要编造已验证接线。
实现带时间戳的本地队列，并处理暂停、跳转、停止、断连与重连：旧事件失效、马达关闭、禁止集中补发。与视觉共用原曲时间和配置。
请先列出数据字段与事件格式，然后实现，交付模拟器/事件文件、固件、配置、接线说明及同步验证步骤；区分软件通过和实物未验证。
```
