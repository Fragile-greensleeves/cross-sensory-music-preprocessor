# 谱图辅助补充

这是可选的分析后处理，不属于自动模型结果。先核对谱图、录音版本和原时间轴，再通过清单补充音符空缺。当前没有自动读谱模型。

```sh
musicprep supplement work/qingtian-full/song-package.json \
  --reference work/qingtian-score-assisted/reference.json \
  --output work/qingtian-score-assisted \
  --audio work/qingtian-full/audio/0c1a866751042dae/canonical.wav
```

清单必须包含原音频 `audio_sha256`、`package_digest(package)` 计算的 `base_package_sha256`、来源 `sources`、方法 `method` 及音符数组 `notes`。每个音符提供 `start`、`end`、`midi` 和 `evidence`。谱图和包含完整音乐内容的清单保留在本地。

处理规则：

- 仅新增空缺音符；与任何原音符重叠的提案都拒绝，保留原音符。
- 空缺中已有实测音高且相差超过半个半音时，拒绝提案。
- 不修改连续音高、和弦、拍点、段落、人声结果或描述，不将谱面合成实测音高。
- 结果使用 `score_assisted_gap` 来源及 `estimated` 状态；保留原任务状态和缓存身份。
- 写入独立目录，逐条记录接受或拒绝原因。参考资料与基准不匹配时拒绝运行。

复核采用独立 `apply_melody_review` 事务：绑定音频与原包摘要，限制修改时间窗，逐项保存修改前后记录，校验后生成新包。原来的仅补空缺规则不变。`review.json` 保存全部证据与修改清单，报告中的复核记录默认折叠，所有音符仍使用同一蓝色。

方法参考：[Basic Pitch](https://github.com/spotify/basic-pitch)、[torchcrepe](https://github.com/maxrmorrison/torchcrepe)、[Essentia PredominantPitchMelodia](https://essentia.upf.edu/reference/std_PredominantPitchMelodia.html)。
